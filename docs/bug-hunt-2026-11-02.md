## SH-01 — P1: A stale write approval destroys concurrent edits

**Location:** `mathagent/tools.py:148–156`; GUI approval wait: `mathagent/gui/hub.py:675–686`.

**Reproduce:** In an Explore conversation, request an edit to `notes.md` and leave the model's write approval open. Edit that file separately, adding a new lemma. Approve the already displayed diff. The executable HTTP reproduction is `gui_storage/repro_stale_write.py`.

**Expected:** Preserve the changed file and report a conflict or ask for approval of a fresh diff. **Observed:** The preview describes replacing only `Original manuscript text.`. The file at approval time also contains `New lemma written while approval was pending.`. Approval replaces everything with `Model replacement.`; `new_lemma_survives=false`, and the tool reports `Wrote notes.md (19 bytes)` without a conflict.

**Cause:** `write_file` reads the old contents before waiting for approval, then writes unconditionally afterward. Re-resolving the path does not check whether its contents changed.

**Proposed fix:** Record the resolved target, existence, identity and content digest used to prepare the diff. After approval, validate that version immediately before writing; refuse or regenerate the preview if it changed, including a file created while approval was pending. Coordinate harness writes per path and use atomic replacement to avoid truncation on failure. Keep explicit conflict behavior for edits made outside SH.

**Regression:** Drive the real HTTP approval workflow, change the temporary source while approval is pending, approve the stale preview, and assert that the new text survives and a conflict is reported.

**Evidence:** `gui_storage/stale_write_results.json`.

## SH-02 — P2: Pausing disables mouse/touch submission of a new message

**Location:** `frontend/src/views/ChatView.tsx:190`, `:235`, `:253` (the `blocked` calculation, mode-message state, and Send button).

**Reproduce:** Start an Assistant answer, click Pause, wait for the paused notice, then type a new question. Tested in the real web app with `repro-paused-ui.cjs` and `serve-ui.py`.

**Expected:** The user can send the new question, as the notice explicitly promises. **Observed:** The draft is editable, but `send_disabled=true`. Pressing Enter submits that exact draft successfully and appends the new user turn. No browser page error was captured. Mouse/touch users encounter a disabled control even though the server supports the operation.

**Cause:** The component calculates `blocked = work.blocked || paused`, while `send()` intentionally rejects only active/queued work, not a paused turn. The UI and handler therefore disagree.

**Proposed fix:** Keep paused status separate from active-work blocking. Permit the draft and Send action for a paused turn when no task blocks the conversation; preserve Resume when the draft is empty. Apply consistent eligibility to button submission and keyboard submission.

**Regression:** Pause a real Assistant turn, type a draft, click Send, and confirm that the paused turn is set aside and the new message runs. Repeat with Enter and with an actually active task.

**Evidence:** `paused-ui-results.json`, `paused-send-disabled.png`.

## SH-03 — P2: Explicit attachments do not override disabled file discovery

**Location:** `mathagent/gui/hub.py:869–887`; intended pinned-file exception: `mathagent/tools.py:53–56,73–76`.

**Reproduce:** Disable general TeX reading, open an Explore or Critic conversation, and explicitly attach `identity.tex`. Request `read_file` for that attached file. See the `explicit_attachment_with_tex_disabled` phase of `gui_storage/repro_attachments.py`.

**Expected:** That deliberately attached file is available; unrelated TeX files remain restricted. **Observed:** `Tool error: The user has not allowed reading .tex files in this workspace; ask them to pin the file or enable that file type`.

**Cause:** `Hub.chat` validates the selected paths and names them in the prompt but never pins them in the current Agent's Workspace.

**Proposed fix:** Call `agent.workspace.pin_files(files)` with the validated selected files before running ordinary chat. Retain the user's general discovery/read settings.

**Regression:** Disable a group, attach one file from that group, and verify that it can be read while a second unpinned file remains inaccessible.

**Evidence:** `gui_storage/attachment_results.json`.

## SH-04 — P2: Fresh review loses Explore/Critic source attachments

**Location:** `mathagent/gui/hub.py:891–892`; `mathagent/gui/store.py:646–673`; review consumer: `mathagent/gui/hub.py:955–958`.

**Reproduce:** With default read permissions, attach `identity.tex` in Explore/Critic, let the model read it and answer, then invoke Fresh review. See the `initial` and `fresh_review` phases of `gui_storage/repro_attachments.py`.

**Expected:** The fresh reviewer can reread the supplied source without general workspace discovery. **Observed:** The initial read succeeds, but the saved user transcript has no `files` field. Fresh review advertises no `read_file` tool. A request to reread the attachment yields `Tool error: Unknown or disabled tool: read_file`.

**Cause:** Ordinary chat keeps the attachment name only in prompt text. Review obtains pins from structured `transcript[].files`, then intentionally clears broad readable file types, leaving no source access.

**Proposed fix:** Carry validated attachment paths through `Hub.chat` and `commit_turn` into the saved user transcript. Retain the original user-facing text separately from the model-only attachment annotation where practical. Continue restricting the reviewer to explicitly supplied sources.

**Regression:** Complete an attachment-based chat turn, invoke Fresh review, and assert that its advertised `read_file` tool reads that same attachment. This needs a separate fix from SH-03: initial pinning does not persist metadata, and persisting metadata does not authorize the initial read.

**Evidence:** `gui_storage/attachment_results.json`.

## SH-05 — P2: Equation-range references silently lose an endpoint

**Location:** `mathagent/writeup.py:74`, `:86–95`, `:128–143`.

**Reproduce:** Start a write-up from plain notes with a template loading `amsmath` and `cleveref`. Return two newly generated labelled equations followed by `\crefrange{eq:first}{eq:last}`. The full fixture is in `research-writeup/repro_writeups.py`.

```tex
\begin{equation}\label{eq:first}x=x\end{equation}
\begin{equation}\label{eq:last}y=y\end{equation}
By \crefrange{eq:first}{eq:last}, both identities hold.
```

**Expected:** Both referenced labels survive. **Observed:** SH deletes `eq:last` and changes its equation to `equation*`. The job says `complete`, `compile.ok=true`, `warnings=[]`, while the actual compile log reports the undefined reference to `eq:last`.

**Cause:** The shared reference regex reads only one argument, including for `crefrange`/`Crefrange`. Both numbering cleanup and missing-reference detection consequently miss the second endpoint.

**Proposed fix:** Share a reference-key extractor that handles both arguments of range commands and all keys of ordinary commands. Use it for numbering preservation and undefined-reference checks. Recognize range commands when loading their required package, too. Preserve the existing protection for labels from the author's material.

**Regression:** Run the actual write-up entry point with both range command variants. Assert that both labels remain and the final compile log contains no undefined endpoint.

**Evidence:** `research-writeup/repro_writeups.out`, `research-writeup/range-undefined-reference.txt`.

## SH-06 — P2: A successfully compiled source export cannot be recompiled

**Location:** `mathagent/writeup.py:423–433`, `:1100–1110`, `:1198–1222`.

**Reproduce:** Provide saved template contents `mystyle.sty` defining `\myR`, and generate a short write-up using `\myR`. Let SH compile/export it, then compile only the exported source in a fresh directory. See the `export` case in `research-writeup/repro_writeups.py`.

**Expected:** The source delivery includes what is needed to compile it. **Observed:** SH reports `complete` and `compile.ok=true`; export contains `writeup.tex` and `writeup.pdf`. The TeX uses `\usepackage{mystyle}`, but `mystyle.sty` is missing. Fresh compilation fails. The reproduced missing dependency is a saved `.sty`; other asset forms were not independently reproduced in this hunt.

**Cause:** Compilation receives template contents and assets in a temporary directory. Export writes only the main TeX and PDF, discarding the required auxiliary source.

**Proposed fix:** Retain a manifest of the safe files actually supplied to compilation and offer/export a complete source bundle with the referenced relative paths. Textual dependencies may alternatively use `filecontents*`; external figures still need packaging. Preserve collision, traversal and overwrite protections.

**Regression:** Compile using saved package/class or bibliography contents and a figure, deliver the source bundle, copy it alone to an empty directory, and compile there. Cover folder export and conversation download.

**Evidence:** `research-writeup/repro_writeups.out`, case `EXPORT`.

## SH-07 — P2: Bibliography grounding accepts a different DOI by prefix

**Location:** `mathagent/writeup.py:679–685`.

**Reproduce:** Supply notes containing `doi:10.1234/example-full`. Have the scripted model cite and provide BibTeX for `doi={10.1234/example}`. Both strings have valid DOI syntax; this controlled example tests identifier equality and does not claim either DOI resolves. See the `doi-prefix` case in `research-writeup/repro_writeups.py`.

**Expected:** The second identifier is not accepted as present in the notes. **Observed:** Its entry is saved in `state.bibliography`, embedded and compiled; `status=complete`, `warnings=[]`.

**Cause:** Grounding tests `identifier in material`, so a strict identifier prefix passes as if it were the complete supplied identifier.

**Proposed fix:** Extract complete typed identifiers from the material and compare normalized DOI/arXiv/zbMATH identities by equality. Handle URL wrappers, punctuation, and intentional arXiv version policy explicitly; a substring or word-boundary test is insufficient for identifiers containing punctuation.

**Regression:** Accept an exact DOI and its URL wrapper, reject a strict DOI prefix, and retain well-defined handling of trailing punctuation and arXiv versions.

**Evidence:** `research-writeup/repro_writeups.out`, case `DOI_PREFIX`.

## SH-08 — P2: Proof admission ignores the explicit specialist output cap

**Location:** `mathagent/cli.py:465–466`; `mathagent/proof.py:238–241`, `:497–498`, `:594–595`.

**Reproduce:** Set solve and verify ceilings to 1,024 tokens each and `--specialist-output-tokens 128`, with context 16,384. Without a cumulative cap the real runner completes, issuing exactly two requests with caps `[128,128]`. Add `--proof-tokens 512`. The total now comfortably covers the maximum combined allowance of 256, yet the runner issues no request and reports that 2,048 tokens are needed. The CLI independently exits 1 for this configuration. See `proof_transport/repro.py`.

**Expected:** Admission uses the explicitly reduced allowances that dispatch enforces. **Observed:** `budget_exhausted`, zero requests, zero token charges; CLI rejects the same feasible job.

**Cause:** Several preflight/reservation checks use the uncapped role ceilings while actual calls apply the specialist cap.

**Proposed fix:** Compute effective role allowances after applying the saved explicit cap, then use those consistently in CLI validation, attempt reservation, verifier admission and call admission. Retain reservation before inference and never silently increase saved budgets.

**Regression:** With ceilings 1,024/1,024, cap 128 and total 512, assert one solve and one verification with capped requests and bounded charges. A budget below the combined required capped allowance should remain rejected.

**Evidence:** `proof_transport/results.json`, `normal_cap128_no_total`, `same_cap128_total512`, and `cli_same_cap128_total512`.

## SH-09 — P2: Native-Ollama keepalives bypass the total working-time limit

**Location:** `mathagent/agent.py:55–66`; `mathagent/proof.py:629–644`.

**Reproduce:** Use the real native `Ollama` client and `ProofRunner`, a 1-second proof budget, and a loopback endpoint sending one blank line every 25 ms for 120 iterations before its final completion. The harness lowers the active socket timeout to roughly the remaining 1 second. See `proof_transport/repro.py`.

**Expected:** Stop around the total deadline with an operational outcome and saved partial work. **Observed:** Active time is about **3.45 seconds**, with `budget_exhausted` recognized only after final completion. A second scenario used about 0.59 seconds for a 0.15-second budget. Independent reruns confirmed the same overrun pattern; exact timings vary.

**Cause:** Blank lines are consumed inside the native transport without yielding to the controller's elapsed check. Incoming bytes renew an idle socket timeout. Continually repeated blank lines can therefore continue beyond the total deadline; an infinite stream was not run. This demonstrates accepted-transport behavior, not typical stock-Ollama traffic.

**Proposed fix:** Carry a total elapsed deadline into the native stream and check it before filtering every raw line. Bound blocking reads by the remaining time or use an equivalent interruptible transport, and check final events as well. Preserve partial evidence and an operational status.

**Regression:** Use a real local HTTP endpoint whose blank keepalives arrive within the idle timeout but continue beyond the total deadline. Assert that the client stops before the endpoint's final completion and that the saved job remains inspectable.

**Evidence:** `proof_transport/results.json`, `time_budget_1_second` and `time_budget_015_seconds`.
